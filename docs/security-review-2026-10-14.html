A bounded review of the existing CLI, media parsers, and browser inspector. The local CLI accepted a valid fixture and rejected wrong dimensions, malformed media, and an invalid rule configuration. This document records that evidence without treating a media linter as a security certificate.

14 October 2026Release baseline: 0.7.0Windows · Node 24.19.0

Scope and responsibility

Victor Solano is the project and security maintainer. This review inspects source at 1d27f00583da34c207906750e51f451120b2d6b6. The accompanying maintenance change adds documentation and a reporting process; it does not alter executable code or publish a new npm release.

Inputs include user-chosen media trees, JSON configuration, and browser file selections. Assets to protect are local file contents, process resources, and the integrity of validation reports. The CLI runs with its caller's filesystem permissions; the hosted inspector is client-side software.

Inspection covered src/scan.ts, config.ts, imageheader.ts, previewfile.ts, previewheader.ts, report.ts, and the browser intake, file-read, report-rendering, and export paths. This is a scoped review, not a claim of an exhaustive vulnerability search.

Inspected trust boundaries

BoundaryExisting controlResidual limit
Selected tree → filesystemRead-only scanning; hidden entries and locale depth are handled by a shared scan plan.File symlinks and directory junctions are followed intentionally. The selected root does not contain every possible read.
Image bytes → header parserCLI reads a 1 MiB prefix. PNG/JPEG structural fields and byte bounds are checked; missing metadata is reported.No complete image decoding, CRC verification, or malware verdict. A metadata budget can reject an otherwise valid file.
Preview bytes → container parserAtom sizes and parent/file bounds are checked. CLI skips encoded payloads; moov allocation is limited to 64 MiB.No overall CLI atom-count, elapsed-time, or file-count budget. Untrusted workloads should run in a restricted process.
Selected browser files → memoryTwo file readers, 128 MiB cumulative metadata budget, 64 MiB moov limit, and 4,096 top-level atom limit per preview. Oversized previews skip payload reads.These checks do not bound the browser's total memory or folder-traversal cost. They are not a sandbox for hostile workloads.
File names and findings → browser markupDynamic names, paths, and messages pass through HTML escaping; export serializes the report as JSON.Reports expose selected names and paths. Review exported reports before sharing. Terminal output is a separate surface.
JSON config → validation decisionsMalformed values and unknown rule identifiers are rejected. Rule levels and dimension arrays are validated.A valid config may disable rules or extend accepted dimensions. Only use a config you trust.
Local media → networkNo CLI network or credential integration was found in inspected source. Browser selection parsing and JSON export are local; bundled examples use a fetch path.Hosted scripts, hosting configuration, and future changes remain part of the trust model. No live traffic or production hosting audit was performed.

Observed CLI behavior

These checks ran the actual node src/cli.ts … --json entry point on local fixtures and small synthetic malformed files. SHA-256 hashes of the input files matched before and after every scenario.

ScenarioExpected resultObserved result
Existing valid screenshot treePass, exit 0Pass, exit 0; no errors
Existing 500×500 screenshot fixtureDimension error, exit 1Fail, exit 1; screenshot-unknown-dimensions
Eight-byte PNG signature and a preview atom extending beyond its fileFormat errors, exit 1Fail, exit 1; screenshot-format and preview-format
Configuration with an unknown rule identifierUsage/config error, exit 2Rejected, exit 2

The existing root suite completed with 305 passing checks, zero failures, and one Windows-specific skip: POSIX directory-read permissions are unavailable through Windows chmod. The existing browser-model suite completed with 19 passing checks and zero failures. Both ran serially on Node 24.19.0, without a build step. The browser-model suite is not a live browser traffic check. No new tests were authored for this review.

What this review does not establish

  • A clean security bill, a CVE, a bug-bounty acceptance, or third-party certification.
  • Production network behavior, hosting account security, signing or update authenticity, or current dependency advisory coverage.
  • A new compiled or packaged release. The documented baseline remains the existing source and published 0.7.0 release.
  • Linux or macOS behavior in this session, complete media decoding, or resource limits beyond the safeguards described above.

For hostile inputs, limit the process or browser's privileges and resources. For a reachable security defect, preserve a minimal harmless reproduction and report it privately.

Report privately through GitHub vulnerability reporting or the contact in SECURITY.md. Victor owns triage, remediation, release coordination, and reporter credit.
